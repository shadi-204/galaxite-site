# Galaxite

موقع قراءة ونشر مانجا ومانهوا مترجمة للعربية. الواجهة الحالية HTML/CSS/JavaScript، مع Supabase للمصادقة والبيانات والتخزين.

## الحالة الحالية

- الواجهة العامة تُحمّل الأعمال المنشورة من جدول `site_works` في Supabase.
- بيانات الفصول في `site_chapters`، وصور الصفحات في جدول `site_chapter_pages` مع ملفات داخل Storage bucket خاص اسمه `galaxite-chapters`.
- قارئ الفصول يطلب روابط مؤقتة للصور من التخزين الخاص. لا توجد حاليًا صور صفحات محفوظة في قاعدة البيانات، لذلك ستظهر الصفحات البديلة حتى يتم رفع صور مصرح باستخدامها.
- المفضلة وتقدم القراءة وبعض تفضيلات الواجهة ما زالت محلية على جهاز القارئ.
- الدفع الحقيقي غير مفعّل؛ `payments-config.js` ليس بوابة دفع إنتاجية.

## التشغيل والنشر

الموقع لا يحتاج عملية build. GitHub Pages ينشر ملفات الواجهة الثابتة من فرع `main`.

1. احتفظ بملفات المشروع كاملة في المستودع.
2. من GitHub افتح Settings ثم Pages.
3. اختر Branch: `main` والمجلد `/` ثم Save.

فرع التطوير ينتج أيضًا نسخة اختبار من خلال [GitHub Actions](https://github.com/shadi-204/galaxite-site/actions/workflows/validate-galaxite.yml): افتح آخر تشغيل ناجح ونزّل artifact باسم `galaxite-static-preview`. هذه نسخة ملفات ثابتة للمراجعة، وليست نشرًا جديدًا على رابط GitHub Pages. لا تُدمج تغييرات الفرع في `main` حتى اعتماد المراجعة.

فرع التطوير الحالي: `backup/pre-galaxite-overhaul-2026-11-28`. التعديلات عليه لم تُدمج في `main` ولم تُنشر للزوار بعد.

## الملفات المهمة

- `index.html`: الواجهة العامة.
- `data.js`: بيانات احتياطية إذا تعذر تحميل الكتالوج الحي.
- `catalog.js`: تحميل الأعمال المنشورة وروابط صفحات الفصول من Supabase.
- `reports.js`: إرسال بلاغات الأعمال والفصول وعرضها وتحديثها من لوحة الإدارة.
- `account.js`: حسابات القراء والمصادقة.
- `auth-config.js`: إعدادات Supabase العامة للواجهة. المفتاح الموجود هنا Publishable/anon فقط، وليس مفتاحًا سريًا.
- `admin.html` و`admin.js`: لوحة الإدارة المحمية.
- `v4.css`: تنسيقات الواجهة والحوار الخاص بالبلاغات.
- `sw.js`: ملفات PWA المؤقتة وإصدار الكاش.
- `supabase/migrations/`: ملفات تغييرات قاعدة البيانات المسجلة في المشروع.

## لوحة الإدارة

افتح `admin.html` على الموقع. تتضمن النسخة الحالية:

- **الأعمال:** إضافة وتعديل وإخفاء/إعادة نشر الأعمال في Supabase.
- **الفصول:** تعديل بيانات الفصل، نشره أو جعله مدفوعًا، ورفع صور الصفحات أو استبدالها في التخزين الخاص.
- **المصادر والأتمتة:** سجل للمصادر وحالة الإذن وروابطها، مع عرض طوابير الاستيراد والمعالجة. تظل المصادر متوقفة حتى نشر عامل الاستيراد والحصول على الإذن.
- **المستخدمون:** عرض الحسابات وتغيير أدوار user/moderator/admin. لا يمكن تعيين مالك جديد من هذه القائمة.
- **البلاغات:** استقبال بلاغات الأعمال والفصول، فتح المحتوى، ثم تحديد البلاغ كمُصلح أو متجاهل أو قيد المراجعة.
- **الإعدادات:** تغيير كلمة مرور حساب الإدارة عبر Supabase Auth.

`siteadmin.html` يحوّل الآن إلى لوحة الإدارة المحمية. بعض إعدادات الواجهة والمدفوعات ما زالت غير مفعّلة، ولا تعرض اللوحة أرقامًا تجريبية على أنها بيانات حقيقية.

## المصادقة والصلاحيات

- تسجيل دخول الإدارة يعتمد على Supabase Auth، ثم يتحقق من دور `owner` في جدول `profiles` عبر الدالة `is_owner()`. البريد وحده لا يمنح أي صلاحية.
- لا يوجد استثناء خاص لبريد وهمي ولا يتم تعطيل تأكيد البريد على مستوى المشروع؛ استخدم حساب Owner مؤكدًا بالفعل.
- أزيلت آليات الترقية الآلية التي كانت مرتبطة بعنوان البريد التجريبي. تعيين دور Owner يتم من صلاحيات قاعدة البيانات المحمية، وليس من بيانات يرسلها المتصفح.
- سياسات RLS تقيد قراءة/تعديل البلاغات والمصادر والمهام إلى المالك/المدير.
- لا تضع `service_role` أو أي كلمة مرور أو مفتاح سري داخل ملفات الواجهة أو GitHub.

## البلاغات

يستطيع القارئ المسجل الدخول إرسال بلاغ من صفحة العمل أو قارئ الفصل. البلاغ يسجل نوع المحتوى ومعرّفه وعنوانه ورابطه وسبب البلاغ والتفاصيل. لوحة الإدارة تقرأ البلاغات وتحدّث حالتها عبر Supabase، ولا توجد مراجعة يدوية إلزامية لكل فصل قبل النشر.

## مشغل OCR التجريبي

أُضيف مشغل أولي في worker/paddle_ocr_batch.py يستخدم PaddleOCR 3.x باللغة الكورية، لاستخراج الكورية والإنجليزية مع الثقة ومضلعات النصوص. توجد اختبارات لوظائف ترتيب الصفحات وتحويل النتائج وتحديد النص منخفض الثقة.

المشغل كود جاهز للتشغيل داخل بيئة عامل منفصلة، لكنه لم يُثبت عليه PaddleOCR أو أوزان النماذج ولم يُشغّل على الفصل كاملًا حتى الآن. لا يترجم ولا ينظف الصور ولا يرفع أو ينشر أي ملف. التفاصيل في worker/README.md.

## المصادر والأتمتة وOCR

تم إنشاء جداول سجل المصادر وطوابير الاستيراد ومعالجة الفصول، مع دوال آمنة لحجز المهام مخصصة لـ `service_role`.

**لكن عامل المعالجة نفسه لم يُنشر بعد.** ما زال مطلوبًا بناء وتشغيل:
- موصلات المصادر واكتشاف الأعمال والفصول.
- تنزيل/استيراد المحتوى المصرح به فقط.
- OCR واكتشاف مواضع النص.
- إزالة النص الأصلي وتنظيف الخلفية.
- الترجمة إلى العربية.
- تركيب النص العربي واختيار الخطوط وضبط الاتجاه والحجم.
- النشر الآلي وتحديث حالة المهمة.

Asura Scans موجود في سجل المصادر بحالة pending ومتوقف. لا يتم الاتصال به أو إعادة نشر محتواه قبل توفر الموافقة اللازمة. استخدم في الاختبارات صفحات تملكها أو لديك إذن باستخدامها.

## التحقق والاختبارات

- يوجد GitHub Actions workflow لفحص JavaScript وملفات HTML والأصول المحلية وإعدادات الموقع وService Worker، ثم بناء نسخة static preview.
- يتم أيضًا فحص صياغة Python وتشغيل اختبارات وحدة لمشغل OCR الأولي الموجود في worker/.
- نجاح الفحوصات الآلية لا يعني اكتمال اختبار المتصفح أو تسجيل الدخول ورفع الصور والبلاغات أو جودة OCR الفعلية.
- يجب إجراء اختبار شامل بحساب Owner وصفحات اختبار مصرح بها، وقبل دمج التغييرات في `main`.

راجع `docs/PROJECT_AUDIT.md` لمعرفة حالة التنفيذ والقيود المتبقية.
